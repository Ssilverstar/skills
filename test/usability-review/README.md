# Agent Observatory 후속 사용성 점검

2026-10-31, DGX Spark에서 실행 중인 웹을 실제 Chromium으로 점검하고 개선했다.
운영 주소: <http://192.168.0.65:8787>. 호스트의 LAN 주소 접속을 검증했으며 Windows 실기기 접속을 대신 검증한 것은 아니다.

## 역할과 작업 방식

- **Claude Opus 5.5 high**: 유일한 구현 총괄. 계약 작성, Argon 지시·승인 처리, diff 리뷰, 통합 수정, 컨테이너 배포.
- **Gemini 4 Argon Medium** (`gemini-4-argon-medium`, Antigravity CLI): HTML·CSS·JS와 신규 UI 테스트 구현. 실제 패널에서 모델을 확인했다.
- **Codex**: 수정 전 실브라우저 진단, 독립 검사, 최종 화면 확인과 Git 정리. Argon에게 별도 구현 지시를 하지 않았다.

작업자는 한 명만 두고 같은 파일의 동시 수정을 피했다. Argon의 결과 없는 중단은 `idle`만 보고 완료로 처리하지 않고 Opus를 통해 재개했다. 작업자 완료 후 작은 수정은 Opus가 소유권을 회수해 처리했다. [계약](contract.md)과 [총괄의 수행·검증 기록](orchestration-record.md)에 상세 근거가 있다.

## 개선 내용

| 문제 | 변경 |
| --- | --- |
| 서버 연결이 끊겨도 Healthy가 남음 | 연결 끊김 표시, 마지막 데이터 유지, 관측 시각·경과 표시, 복구 상태 표시 |
| 만료된 한도가 현재 최대 사용률로 표시됨 | 만료 항목을 현재 KPI에서 제외하고 갱신 대기로 표시. 과거 관측값을 0으로 바꾸지 않음 |
| 새로고침·정렬 시 펼친 정보와 포커스가 사라짐 | 열린 상세, 정렬·검색·필터, 포커스와 스크롤 위치 보존 |
| 스킬 전체 목록이 길고 비활성 복제본이 중복됨 | 공통 선택을 기본으로 표시하고 활성→미확인→비활성 순으로 대표 행 선택. 전체 등록/상태 필터와 행 수, 개요·목록·MCP 바로가기 추가 |
| 작은 모바일 조작부와 흐린 안내 문구 | 모바일 주요 조작부 높이 42px, 보조 글자 최소 12px, 주야간 대비 개선 |
| 차트의 접근성 정보 부족 | SVG 요약·제목, 선택 범위 `aria-pressed`, 반복 경고 낭독 완화 |
| 세션 토큰과 청구량·실행 모델 혼동 | 관측 세션 누적이며 청구량이 아님을 표시. Antigravity 기본값은 ‘설정 모델’로 명시 |

공통 스킬 36개 선택 정책과 MCP 설정, 수집 서버·OTel·DB 보존 정책은 변경하지 않았다. 최종 통합 시 공통 기본 목록은 **145행(4×36 + 저장소 원본 1)**, 전체 등록 목록은 836행이었다. 전체 수는 로컬 설치 상태에 따라 변한다. Antigravity의 36개 상태는 **미확인**으로 유지한다.

## 검증과 정정

- [수정 전 독립 검사](before-checks.json): 7개 중 6개 실패, 영어 전용 표시는 통과.
- [수정 후 독립 검사](independent-results.json): 연결 실패·복구, 만료 한도, 상세/포커스 보존, 차트 접근성, 모바일, 영어 전용 7개.
- [총괄 회귀 검사](regression-results.json): 스킬 중복/필터/바로가기, 실제 body 스크롤 보존, 대비·조작부와 1024px까지 포함한 넘침 검사 11개 통과.
- [기존 브라우저 E2E](e2e-after.json): 정렬·영어/한국어·주야간·숫자/미확인·XSS·대기 상태 등 12개.
- [화면 측정](visual-results.json): 3개 뷰 × 3개 폭(390/768/1440) × 2개 테마 = 18조합. 실제 화면 캡처는 `test/.local/usability-review/final/`에 두고 커밋하지 않는다.
- 단위 검사: 저장소 프로필 5 + 프로브 10 + 서버 41 + UI 51 = **107개**. UI 51개는 Codex도 직접 다시 실행했다.

초기 `documentElement.scrollWidth` 검사만으로는 768px 헤더 잘림을 놓쳤다. body 검사와 실제 스크린샷으로 발견한 [추가 실패 기록](visual-tablet-regression.json)을 남기고 최종 검사에 body를 포함했다. 1100px 이하 헤더 줄바꿈과 토큰 단위 줄바꿈을 보완한 뒤 **최종 18조합 통과·배포 소스 해시 일치**를 확인했다. 수정 전 스크롤 리셋 주장은 Playwright 클릭의 자동 스크롤 부작용이 섞여 유효한 증거로 채택하지 않았다.

[최종 종료 명세](closure.json): Opus의 조건부 merge 동의 조건(독립 검사와 최종 화면 검사)을 충족했고, 최신 UX-001/UX-002 결과와 실제 입력 대기 화면·배경 작업 종료를 확인한 뒤 두 작업자 패널을 닫았다. Codex 패널 하나만 유지한다.

검사 코드: [independent_check.py](independent_check.py), [regression_check.py](regression_check.py), [visual_check.py](visual_check.py). Playwright 1.63과 Chromium이 설치된 Python 환경에서 저장소 루트 기준으로 실행한다. 네트워크 실패·만료 한도는 브라우저 요청 가로채기만 사용하며 운영 데이터를 바꾸지 않는다. 수정 전 결과는 당시 검사 버전의 기록이고, 최종 검사에는 이후 발견한 body 넘침 검사도 포함된다.

## 한계와 운영상 결론

이번 구성은 총괄 한 명과 구현자 한 명으로 책임을 명확히 했고, Codex의 독립 검사가 태블릿 잘림을 추가로 발견했다. 다만 중단 복구·승인·검토 대기가 있었으므로 단독 모델보다 빠르거나 저렴하다고 결론 내릴 수 없다. 동일 과제를 Astra/Opus 단독으로 반복한 통제 벤치마크는 아니다.

대비 검사는 측정 대상 문구에 한하며 전체 WCAG 인증이 아니다. Antigravity 토큰의 모델별 이력 분해, 공급자별 네이티브 OTel 지원 범위 등 기존 수집 제약도 그대로다. 화면 개선을 전체 에이전트의 완전한 실시간 사용량 계측으로 해석하지 않는다.
