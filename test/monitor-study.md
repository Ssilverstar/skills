# 모니터링 구현 · Herdr 운영 비교 기록

> 후속 UI·보존·동일 스킬/MCP 작업은 [최종 보고](final-report.md)를 우선합니다. 아래 검증 개수와 사용량은 첫 구현 차수의 관측입니다.

2026-10-31 구현·운영 시험 결과. 모니터링 서버는 독립 실행 중이며, 비교 대상의 단독 기준 실행은 하지 않았습니다.

## 구현 결과

- 웹: <http://127.0.0.1:8787> — 에이전트 사용량/구독, 하드웨어·추론, 스킬 현황의 3개 메뉴.
- Docker Compose의 앱·OpenTelemetry Collector·Prometheus와 SQLite/Prometheus 볼륨, 별도 systemd 사용자 수집기. Herdr 패널과 별개로 동작합니다. 수집기는 로그인 시 시작하며 linger는 변경하지 않았습니다.
- Codex·Claude·OpenCode는 로컬 기록의 모델별 토큰을 집계합니다. Antigravity는 공식 상태줄로 실제 세션 누적 입력/출력을 확인했으며, 과거 모델별 분해·캐시와 미관측 세션은 제공하지 않습니다.
- 구독 한도는 Codex 계정 API, Claude 공식 상태줄, Antigravity 공식 `/usage`에서 관측합니다. 로컬 Qwen에는 구독 한도가 없으며 전력 비용을 달러로 추정하지 않습니다.
- GB10 전력·온도·이용률과 시스템 공유 메모리를 표시합니다. GPU 전용 VRAM 카운터는 N/A를 유지합니다. 이미지 이름은 vLLM이지만 실제 엔진은 **llama.cpp**로 확인했으며, 설치된 vLLM 패키지 버전과 구분했습니다.
- 스킬 원본·등록·활성·호출 요청 증거를 구분합니다. `graft`, `archify`, `ponytail-help` 등 기존 필수 스킬/활성 정책을 이번 구현으로 삭제하거나 바꾸지 않았습니다.

[운영·재실행 가이드](monitor/README.md), [배포 검증](results/monitor-deployment.json), [실브라우저 검증](results/monitor-e2e.json), [수집 근거](monitor/research.md).

최종 검증: 수집기 9건, 서버·통합 28건, UI 14건, 기존 저장소 테스트 3건 통과. 서버 테스트의 SQLite ResourceWarning도 재실행 stderr에서 0건을 확인했습니다. 실제 Chromium에서는 3개 메뉴·390px 폭·스킬 검색·미수집/stale·문자열 안전 표시 등 6개 시나리오가 통과했고 브라우저 오류는 없었습니다. [검사 명령·결과](results/monitor-checks.json).

## 역할과 수정 이력

- 최초 해석: Codex가 수집기를 만들고 Claude가 웹앱을 직접 구현, OpenCode는 독립 검토.
- 사용자 정정: `Agents`는 Claude가 Gemini와 OpenCode를 직접 조정하는 작업자 그룹. 최초 해석은 user-guide의 위임 목적과 달랐음.
- 수정: Codex가 Claude의 진행을 중단하고 역할 변경을 전달. 기존 서버 파일 보존, Claude가 프런트엔드를 Gemini에, TC/검증을 Qwen에 계약으로 배정하고 통합하도록 변경.
- 집 환경의 명시적 대체: Gemini CLI → Antigravity/Gemini 3.8 Flash, GLM → OpenCode/Qwen3.8 Flash. 회사 환경 승인이나 동일 성능을 의미하지 않음.
- 현재 실제 배치: 왼쪽 Codex, 가운데 Claude/Opus, 오른쪽 위 OpenCode/Qwen·아래 Antigravity/Gemini. 작업자에 대한 구현 지시는 Claude가 발행. Codex는 호스트 수집과 독립 검증 소유.

사용자 정정 2회(작업자 그룹 해석, 조정 주체 재확인)를 현재 방식의 조율 부담으로 기록합니다. 마지막 비교 요청은 범위 추가이며 실패 횟수로 세지 않습니다.

## 측정 범위

첫 호스트 스냅샷 관측은 2026-10-31T03:20:17Z이며 이미 작업이 시작된 뒤입니다. 이후 사용자 요청 로그에서 시작 시각 **2026-10-31T03:13:52.966Z**를 확인해 [measure_run.py](monitor/measure_run.py)로 해당 시간 이후 지정 세션의 토큰을 분리했습니다. [부분 실측](results/monitor-run-usage.json)은 캐시 포함 토큰이며 구독 청구액이 아닙니다. 측정 파일의 `measured_at`까지 기록된 응답만 포함하므로 최종 답변 등은 빠집니다. Antigravity는 시험 도중 관측한 세션 누적이며 정확한 시작 시각 차분이 아닙니다. 동등한 단독 기준 실행이 없어 절감률은 계산할 수 없습니다.

- 수집기: 입력 토큰에 캐시 포함, 추론은 출력의 부분집합. Codex 응답 ID, Claude 메시지 ID로 중복 제거. 에이전트 세션 수는 모델별 합산하지 않음.
- Qwen이 초기 읽기 전용 검토에서 캐시 중복·시계열 누적 중복·구독 관측 시점·GB10 공유 메모리·설치와 호출 증거 구분을 지적. 수집 계약과 테스트에 반영.
- Claude 기존 GateGuard 훅이 파일 생성 시 여러 차례 거절하여 설명·재시도 비용 발생. 훅을 해제하지 않고 필요한 사실을 먼저 제시하는 절차로 대응.
- Antigravity는 앞선 smoke에서 headless read_file 거절이 exit 0/SUCCESS로 보고됨. 대화형 실제 결과 확인이 필요함을 개선 스킬에 반영.

## 관측한 장점과 비용

- 분담은 실제로 수행됐습니다. Gemini가 FE-001~004를 구현하고 Qwen이 서버 검증 24건을 작성했습니다. Claude가 통합 회귀 4건과 서버·컨테이너를 담당했습니다. Codex는 호스트 수집기·네이티브 상태줄 연동·독립 브라우저 검증을 담당했습니다. [FE 결과](monitor/contracts/results/FE-001.yaml), [QA 결과](monitor/contracts/results/QA-001.yaml).
- 교차 검증에서 누락 정적 파일의 응답 종료, NaN/Infinity, GiB 표기, 실제 추론 엔진 표기, 한도 막대·미래 초기화 시각, 테스트 연결 미정리 문제를 찾아 수정했습니다. 모든 발견을 모델 하나의 우월성으로 해석할 수는 없습니다.
- Opus 관측상 Gemini의 반복 검사 승인이 약 20회, Qwen의 첫 테스트 파일 작성까지 약 25분이 들었습니다. Qwen 최종 UI에는 약 30분/20 tok/s가 표시됐습니다. 통제된 성능 시험이나 승인 이벤트 전수 계수는 아닙니다. [Opus 검토 원문](herdr-orchestrate-review-claude.md).
- 작은 FE 피드백을 3차례 더 위임하는 동안 승인·재검증 왕복이 발생했습니다. 마지막 색상과 테스트 cleanup 수정은 작업자 완료 후 Claude가 소유권 회수를 기록하고 직접 처리했습니다.
- 작업자의 미실행 smoke 성공 보고뿐 아니라 Claude의 `exit 0 → ResourceWarning 해소` 판단도 독립 검증에서 정정했습니다. 최종 검증은 종료 코드·stderr·하위 테스트 수·실브라우저를 함께 확인합니다. QA 결과의 경고 설명은 통합 전 관측이며, 최종 상태는 배포/검증 기록을 우선합니다.

## 다음 작업에 적용할 운영 기준

작은 변경은 Astra 또는 Opus 한 명이 끝내고, 분리 가능한 큰 작업에서는 **총괄 한 명 + 필요한 작업자만** 쓰는 구성을 권합니다. 이번처럼 사용자가 Claude를 총괄로 지정했다면 계속 Claude가 Gemini/OpenCode를 조정합니다. Codex 독립 검토는 설계 확정·통합 완료처럼 중요한 시점에 집중하면 상시 이중 검토의 부담을 줄일 수 있습니다. Astra와 Opus 중 어느 모델이 총괄로 더 우수한지는 이번 결과만으로 판단하지 않습니다.

Qwen에는 입력 스키마·참조 파일·테스트 예제를 좁혀 주고 첫 산출물 확인 시점을 계약에 넣습니다. Gemini의 UI 결과는 단위 테스트뿐 아니라 실제 화면으로 확인하고 피드백을 모아서 전달합니다. 작업 완료 후 몇 줄의 통합 수정은 소유권 이전을 기록하고 총괄이 처리합니다.

이를 [herdr-orchestrate 스킬](../skills/herdr-orchestrate/SKILL.md)과 [워크플로](../herdr/workflows/claude-workers.md)에 반영했습니다. Opus 의견의 승인 분리·미실행 표시·작은 수정 통합·설정 반영 확인·진행 체크포인트를 적용했습니다. 새 스킬은 후속 합의에 따라 공통 36개 목록에 포함해 네 에이전트에 배포했습니다.

첫 차수 종료 시에는 패널과 서버를 유지했습니다. 이후 사용자가 전체 완료 후 패널 정리와 main 머지를 요청했습니다. 최종 상태는 [완료 기록](final-report.md#최종-완료-기록)을 확인합니다.
