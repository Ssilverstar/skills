# Opus 5.5 high 비교 검토 — 2026-10-31

사용자 요청에 따라 현재 Herdr 탭 오른쪽 `w3:p5`에 Claude Code 2.1.314를 실행했습니다. 실행 인자는 `--model claude-opus-5-5 --effort high`이며 패널의 모델·effort 표시도 확인했습니다. 검토 에이전트 이름은 `opus-skill-review`입니다. 이 문서는 그 에이전트의 두 차례 답변을 Codex가 요약하고, 확인된 사실과 미확인을 구분한 기록입니다. Opus 답변은 공급업체 공식 권장 기준이 아닙니다.

## 결론

**삭제 대신 비활성화하고 백업한 방식은 타당하지만, 먼저 29개를 고른 뒤 나머지 334개를 일괄 비활성화한 선정 기준은 충분하지 않았습니다.** 사용자가 쓰는 기능·실제 도구 환경·스킬 본문과 트리거·설명 예산을 먼저 확인했어야 합니다.

Ponytail은 자동화·다중 에이전트 도구로 분류할 대상이 아니었습니다. 본체는 YAGNI·과설계 방지 원칙이고, review는 과설계 검토, audit는 저장소 감사, debt는 유보한 기술 부채 추적, help/gain은 안내·효과 설명입니다. 사용자가 모두 쓴다고 명시했으므로 아래 6개는 복구했고 사용자 필수로 보존합니다.

`ponytail:ponytail`, `ponytail:ponytail-review`, `ponytail:ponytail-audit`, `ponytail:ponytail-debt`, `ponytail:ponytail-help`, `ponytail:ponytail-gain`.

Opus의 구체적인 추가 설정 제안은 **Python 2개 복구, skill-stocktake 1개 비활성**입니다. 적용한다면 활성 36개가 되지만, 36은 목표가 아니라 선택 결과입니다. 사용자가 타당성 검토를 먼저 요청했으므로 이 제안은 적용하지 않았습니다.

## 검토 과정에서 바로잡은 내용

- Opus는 처음에 정적 `mcp_servers` 목록에 브라우저가 없다는 이유로 `browser-qa`를 제외하자고 했습니다. 이 세션에 실제 `mcp__cua_repl` 및 browser/unified-computer-use 플러그인이 제공된다는 근거를 전달하자 해당 판정을 철회했습니다. 도구 사용 가능 여부는 실제 제공 도구까지 확인해야 합니다.
- App 카탈로그와 로컬 목록의 차이 9개를 “로컬에서 제어할 수 없다”고 단정한 부분도 철회했습니다. 정체와 제어 가능성은 아직 확인하지 않았습니다.
- 최초 29/334와 현재 35/328을 구분해 기록한 문서는 모순이 아니라 변경 이력임을 확인했습니다.
- Opus의 “기능군당 하나” 권고는 실질 중복에만 적용하는 것이 타당합니다. 결함 리뷰와 과설계 리뷰, 일반 TDD와 pytest 전문 지침처럼 서로 보완하는 스킬을 같은 이름의 기능군이라는 이유로 합치지 않습니다.

## 다음 선정 기준

1. 사용자 필수 스킬은 먼저 고정합니다. Ponytail 전체가 해당합니다.
2. 실제 작업·프로젝트 근거와 기능 차이를 확인합니다. 사용 빈도가 확인되지 않으면 미확인으로 기록합니다.
3. 실제 사용 가능한 도구와 경로를 확인합니다. 특정 MCP·Claude 훅·전용 에이전트를 전제로 한다는 이유만으로 대체 가능성까지 검토하지 않고 제외하지 않습니다.
4. 본문과 트리거가 실질적으로 겹치는 항목을 비교합니다. 본문이 길거나 기능군 이름이 같다는 이유만으로 중복이라고 판정하지 않습니다.
5. 이름·설명·경로가 차지하는 목록 예산을 확인하고, 트리거를 보존하는 범위에서 불필요하게 긴 설명을 줄일 후보를 고릅니다. 이번에는 스킬 설명을 수정하지 않았습니다.
6. 변경된 구성은 새 세션의 렌더 결과로 검증합니다. 로컬 파싱 오류 0개만으로 skill budget 경고가 해소됐다고 판단하지 않습니다.

## 실제 상태와 남은 한계

- **활성 35개·비활성 328개**, Ponytail 6개 전부 활성. 로컬 `skills/list`에서 이름 집합과 파싱 오류 0개를 재검증했습니다.
- 최초 비활성 334개의 전체 이름은 [변경 내역](skill-changes-2026-10-31.md)에 있고, 이 중 Ponytail 6개만 복구했습니다.
- 사용자 화면의 남은 경고는 **skill budget 초과**로 확인됐습니다. 사용자의 요청에 따라 이번에는 선정 타당성을 먼저 검토했고, 경고 해소를 위한 추가 설정 변경은 하지 않았습니다.
- Opus도 비활성 328개 전체 본문을 읽은 것은 아닙니다. 후보 약 20개의 본문과 전체 목록·설명을 비교했으므로 전수 품질 감사로 보지 않습니다.
- 실제 사용 빈도는 조사하지 않았습니다. 프로젝트 파일의 존재는 업무 관련성의 단서이며 사용 빈도의 증거는 아닙니다.
- 현재 구성의 새 세션 렌더 결과와 브라우저 API 호환성은 미검증입니다. 오른쪽 검토 패널은 사용자가 결과를 확인할 수 있도록 열어 둡니다.
